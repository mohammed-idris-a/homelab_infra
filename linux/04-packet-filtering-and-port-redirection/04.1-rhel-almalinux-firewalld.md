# 04.1 — RHEL / AlmaLinux: Packet Filtering, Port Redirection & NAT

## Overview

Hands-on firewall lab completed as part of LFCS preparation.

This lab focuses on **firewalld** and covers:

* Opening TCP ports
* Rich rules for source-specific access
* Port forwarding / redirection
* Masquerading
* IPv4 packet forwarding
* Removing firewall rules
* Inspecting active firewall configuration
* Troubleshooting firewall command syntax

The exercises were performed on an AlmaLinux system using `firewall-cmd`.

> Hostnames, usernames, IP addresses, and other environment-specific values are sanitized for public documentation.

# Mental Model

Before choosing a `firewall-cmd` operation, identify **what you are trying to accomplish**:

```text
                    Incoming / Outgoing Traffic
                              │
              ┌───────────────┼────────────────┐
              │               │                │
              ▼               ▼                ▼
        Allow a port    Restrict by source   Redirect traffic
              │               │                │
              ▼               ▼                ▼
        --add-port       --add-rich-rule   --add-forward-port
              
                              │
                              ▼
                    Private network → Internet
                              │
                              ▼
                       --add-masquerade
                              │
                              ▼
                    IPv4 forwarding enabled
```

The key is to distinguish **packet filtering** from **packet forwarding/NAT**.

# 1. Allow Incoming TCP Port

## Scenario

A service is listening on TCP port `8080` and incoming connections to that port need to be allowed.

## Command

```bash
sudo firewall-cmd --add-port=8080/tcp
```

## Verify

```bash
sudo firewall-cmd --zone=public --list-all
```

The port should appear under:

```text
ports:
  8080/tcp
```

### Concept

```text
Client
  │
  │ TCP/8080
  ▼
Firewall
  │
  │ allowed
  ▼
Service
```

This is a basic **port filtering** operation.

---

# 2. Port Redirection / Forwarding

## Scenario

A client connects to port `8081` on the AlmaLinux gateway, but the traffic needs to be forwarded to another internal server on port `80`.

Sanitized example:

```text
Client
  │
  │ TCP/8081
  ▼
AlmaLinux Gateway
  │
  │ TCP/80
  ▼
Internal Server
192.168.10.50
```

## Command

```bash
sudo firewall-cmd --add-forward-port=port=8081:proto=tcp:toaddr=192.168.10.50:toport=80
```

## Verify

```bash
sudo firewall-cmd --zone=public --list-forward-ports
```

Expected:

```text
port=8081:proto=tcp:toport=80:toaddr=192.168.10.50
```

The complete firewall configuration can also be inspected with:

```bash
sudo firewall-cmd --zone=public --list-all
```

## Remove the Forwarding Rule

```bash
sudo firewall-cmd --remove-forward-port=port=8081:proto=tcp:toaddr=192.168.10.50:toport=80
```

Verify:

```bash
sudo firewall-cmd --zone=public --list-forward-ports
```

### Concept

Port forwarding changes **where matching traffic is sent**.

```text
TCP/8081
    │
    ▼
AlmaLinux
    │
    └──────► Internal Server TCP/80
```

This is different from simply allowing port `8081`.

# 3. Masquerading / NAT

## Scenario

An internal server has a private IP address and needs to access the Internet through the AlmaLinux machine acting as its gateway.

Sanitized example:

```text
Internal Server
192.168.10.50
      │
      │ private traffic
      ▼
AlmaLinux Gateway
      │
      │ NAT / masquerading
      ▼
   Internet
```

The gateway uses **masquerading** so that outgoing traffic appears to originate from the gateway's external address.

## Enable Masquerading

```bash
sudo firewall-cmd --add-masquerade
```

Verify:

```bash
sudo firewall-cmd --query-masquerade
```

Expected:

```text
yes
```

## Enable IPv4 Forwarding

For the AlmaLinux machine to route IPv4 packets between interfaces, IPv4 forwarding must be enabled.

Check the current setting:

```bash
sudo sysctl net.ipv4.ip_forward
```

Enable it for the current runtime:

```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

Verify:

```bash
sudo sysctl net.ipv4.ip_forward
```

Expected:

```text
net.ipv4.ip_forward = 1
```

> Enabling IPv4 forwarding and enabling firewall masquerading are related but separate operations. Forwarding allows the kernel to route packets; masquerading performs the required source-address translation for the NAT scenario.

## Remove Masquerading

```bash
sudo firewall-cmd --remove-masquerade
```

Verify:

```bash
sudo firewall-cmd --query-masquerade
```

Expected:

```text
no
```

# 4. Source-Specific Access Using Rich Rules

## Scenario

TCP port `8080` should be permitted only for traffic originating from a specific subnet.

Sanitized example:

```text
Source subnet
192.168.20.0/24
      │
      │ TCP/8080
      ▼
AlmaLinux Firewall
      │
      ▼
    ACCEPT
```

## Add the Rich Rule

```bash
sudo firewall-cmd --add-rich-rule='rule family="ipv4" source address="192.168.20.0/24" port port="8080" protocol="tcp" accept'
```

## Verify

```bash
sudo firewall-cmd --list-rich-rules
```

Expected:

```text
rule family="ipv4" source address="192.168.20.0/24" port port="8080" protocol="tcp" accept
```

## Remove the Rich Rule

```bash
sudo firewall-cmd --remove-rich-rule='rule family="ipv4" source address="192.168.20.0/24" port port="8080" protocol="tcp" accept'
```

Verify:

```bash
sudo firewall-cmd --list-rich-rules
```

---

# Understanding a Rich Rule

Break the rule into its components:

```text
rule
 │
 ├── family="ipv4"
 │
 ├── source address="192.168.20.0/24"
 │
 ├── port port="8080"
 │
 ├── protocol="tcp"
 │
 └── accept
```

| Component                          | Meaning                       |
| ---------------------------------- | ----------------------------- |
| `rule`                             | Defines a rich firewall rule  |
| `family="ipv4"`                    | Applies to IPv4 traffic       |
| `source address="192.168.20.0/24"` | Specifies the source network  |
| `port port="8080"`                 | Matches destination port 8080 |
| `protocol="tcp"`                   | Matches TCP traffic           |
| `accept`                           | Allows matching traffic       |

### Important

An `accept` rich rule for one source **does not automatically mean that everyone else is explicitly denied**.

The traffic that does not match the rule continues through the firewall's normal policy and other applicable rules.

This distinction is important when troubleshooting firewall behavior.

# Troubleshooting

## Incorrect Rich Rule Syntax

An initial attempt to create the rich rule failed because the command syntax was incorrect.

The first attempt resulted in:

```text
Error: No closing quotation
```

The next attempt incorrectly included `rich` as an element and resulted in:

```text
Error: INVALID_RULE: unknown element rich
```

The rule was corrected to the proper syntax:

```bash
sudo firewall-cmd --add-rich-rule='rule family="ipv4" source address="192.168.20.0/24" port port="8080" protocol="tcp" accept'
```

The rule was then successfully added and verified.

### Lesson

When a `firewall-cmd` command fails:

1. Read the exact error.
2. Check the command structure.
3. Verify the required syntax from the documentation.
4. Re-run the command only after correcting the syntax.
5. Verify the resulting firewall state.
